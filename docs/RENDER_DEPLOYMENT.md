# Render Deployment

`render.yaml` defines the API, the frontend, and three cron jobs. The API uses a **persistent disk** (`/var/data`) for its SQLite database, so it needs a paid instance type (Starter or above) and runs as a single instance.

## Backend (pen2pro-api) environment

Required:
- `ENVIRONMENT=production`
- `JWT_SECRET_KEY` (generated by `render.yaml`; never use a default)
- `PEN2PRO_DB_PATH=/var/data/pen2pro.db` (set by `render.yaml`)
- `ADMIN_ACCESS_KEY` and `ADMIN_DASHBOARD_ENABLED=true` for the admin dashboard
- `ADMIN_EMAILS` (your login email) for owner access in the dashboard and owner-only tools
- `FRONTEND_URL` (your site URL; used for CORS and Stripe redirects)
- `OPENAI_API_KEY`, `OPENAI_MODEL_BLUEPRINT`, `OPENAI_MODEL_WEBSITE`
- `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`
- `STRIPE_PRICE_STRATEGIST` ($100 one-time), `STRIPE_PRICE_PRO_MONTHLY`, `STRIPE_PRICE_ELITE_MONTHLY`, `STRIPE_PRICE_FOUNDERS_LIFETIME`
- `ALLOW_TEST_TIER_ACCESS=false`

Optional: `RATE_LIMIT_BLUEPRINT_PER_HOUR`, Twilio and ElevenLabs keys for the voice agent.

## Frontend (pen2pro-frontend) environment

- `VITE_API_BASE_URL` (the API's public URL)
- `VITE_STRIPE_PUBLISHABLE_KEY`
- `VITE_AFFILIATE_*` links (optional; Vite bakes these in at build time, so redeploy after changing them)

## Stripe

1. Create the four prices and put their IDs in the variables above.
2. Add a webhook endpoint `https://<api-host>/api/stripe/webhook` with events `checkout.session.completed`, `customer.subscription.updated`, `customer.subscription.deleted`, and copy its signing secret into `STRIPE_WEBHOOK_SECRET`.

## After the first deploy

1. Create an account, trigger a redeploy, and confirm you can still sign in. That proves the disk is mounted and data survives.
2. Make a test-mode purchase of each plan and confirm it unlocks.
3. Back up `/var/data/pen2pro.db` regularly (Render disk snapshots, or copy the file).
